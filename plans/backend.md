## Notes

Layering is strict. Routers under `app/routers/` only handle HTTP and validation. Domain logic lives in `app/services/`. Persistence (SQLAlchemy models, repositories) stays in `app/db/`. Routers never import models directly, and ORM models never leak into the response. Pydantic schemas at the edge, always.

Alembic owns the schema. Never call `Base.metadata.create_all` at startup, even "just for dev". The whole point is keeping prod and dev in sync via migrations.

Status values are an enum, not free text. Mapping them to a PostgreSQL `ENUM` type via SQLAlchemy gives you DB-level validation as a backstop, on top of the Pydantic check at the API edge.
