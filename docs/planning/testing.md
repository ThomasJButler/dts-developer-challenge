Branch: `feature/testing-polish`. Depends on testing-1.

- [x] Backend: a malformed UUID returns 400, not 500. Oversized titles are rejected. A past due-date is allowed (backend) but flagged in the frontend.
- [x] Frontend: accessibility pass with axe-core or a manual checklist. Focus order, `for`/`id` pairs on labels, error-summary links to fields.
- [x] README: how to run, screenshots, a short architecture diagram.

Done when a fresh assessor can clone, run, and understand the project from the README alone, and the a11y checklist is signed off.

## What testing-2 actually delivered

The backend edges were already satisfied on `main` when testing-2 started — the work was verification, not new code. The frontend a11y bar was raised by replacing the optional axe-core/manual checklist with a Playwright + `@axe-core/playwright` suite that runs against the live stack on every PR. The README was rewritten in the candidate's voice with desktop and mobile screenshots, generated by the same Playwright project (`npm run e2e:screenshots`). A third CI job, `e2e`, exercises the full compose stack on every push.

## Notes

The Postgres service container in GitHub Actions needs a healthcheck just like the local compose file, otherwise pytest will race the database on cold starts.

a11y isn't a one-time pass. Every form change risks a regression: missing `for`/`id`, lost focus, error summary links that point to nothing. testing-2 puts axe-core in the CI loop so those regressions surface on the PR that introduces them, not weeks later.
