# API contract

The backend exposes a JSON HTTP API for managing tasks. This document is the contract; both the backend implementation and the frontend client code against it. If the backend implementation needs to differ, update this document in the same commit.

Base URL: `http://localhost:8000` in local dev. Configurable via `API_BASE_URL` on the frontend.

OpenAPI is generated by FastAPI and served at `/docs` (Swagger UI) and `/redoc`. This Markdown document is the human-readable contract; the generated OpenAPI must stay consistent with it.

## Conventions

- All request and response bodies are JSON with `Content-Type: application/json`.
- Timestamps are ISO 8601 with explicit UTC offset (`Z`). The API rejects naive (offset-less) timestamps.
- IDs are UUID v4 strings.
- Successful responses return `200 OK` for reads, `201 Created` for creates, `204 No Content` for deletes.
- Errors use a Problem-Details body (RFC 7807-ish) — see [Error shape](#error-shape).

## Task resource

| Field         | Type                            | Notes                                                                |
|---------------|---------------------------------|----------------------------------------------------------------------|
| `id`          | string (UUID)                   | Server-assigned on create.                                           |
| `title`       | string                          | Required. 1–255 characters. Trimmed.                                 |
| `description` | string or null                  | Optional free text.                                                  |
| `status`      | string enum                     | One of `todo`, `in_progress`, `done`. Defaults to `todo` on create.  |
| `due_at`      | string (ISO 8601, UTC) or null  | Optional. Must include a timezone offset. Stored in UTC.             |
| `created_at`  | string (ISO 8601, UTC)          | Server-assigned. Read-only.                                          |
| `updated_at`  | string (ISO 8601, UTC)          | Server-maintained. Read-only.                                        |

### Status values

- `todo` — newly created, not yet started.
- `in_progress` — actively being worked on.
- `done` — completed.

Any other value is rejected at the API boundary with `422 Unprocessable Entity`.

## Endpoints

| Method | Path                       | Purpose                       | Success | Errors                  |
|--------|----------------------------|-------------------------------|---------|-------------------------|
| POST   | `/tasks`                   | Create a task                 | 201     | 422                     |
| GET    | `/tasks`                   | List all tasks                | 200     | —                       |
| GET    | `/tasks/{id}`              | Read one task                 | 200     | 400, 404                |
| PATCH  | `/tasks/{id}/status`       | Update a task's status        | 200     | 400, 404, 422           |
| DELETE | `/tasks/{id}`              | Delete a task                 | 204     | 400, 404                |

There is no pagination. The list endpoint returns every task. This is intentional given the scope of the brief.

---

### POST /tasks

Create a new task. `status` defaults to `todo` if omitted.

**Request**

```json
{
  "title": "Review case file CR-2026-0142",
  "description": "Initial triage and assign to clerk.",
  "status": "todo",
  "due_at": "2026-05-20T09:00:00Z"
}
```

**Response — 201 Created**

```json
{
  "id": "8b1c9d3e-7f2a-4d6b-9e5c-1a2b3c4d5e6f",
  "title": "Review case file CR-2026-0142",
  "description": "Initial triage and assign to clerk.",
  "status": "todo",
  "due_at": "2026-05-20T09:00:00Z",
  "created_at": "2026-05-12T14:30:00Z",
  "updated_at": "2026-05-12T14:30:00Z"
}
```

**Response — 422 Unprocessable Entity**

Returned for missing required fields, oversize title, unknown status, or naive `due_at`.

```json
{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Request body failed validation",
  "errors": [
    { "field": "title", "message": "field required" },
    { "field": "due_at", "message": "datetime must include a timezone offset" }
  ]
}
```

### GET /tasks

List every task. No filtering, no pagination.

**Response — 200 OK**

```json
[
  {
    "id": "8b1c9d3e-7f2a-4d6b-9e5c-1a2b3c4d5e6f",
    "title": "Review case file CR-2026-0142",
    "description": "Initial triage and assign to clerk.",
    "status": "todo",
    "due_at": "2026-05-20T09:00:00Z",
    "created_at": "2026-05-12T14:30:00Z",
    "updated_at": "2026-05-12T14:30:00Z"
  }
]
```

An empty list returns `[]` with `200 OK`, not `404`.

---

### GET /tasks/{id}

Read a single task by ID.

**Path parameters**

- `id` — UUID v4.

**Response — 200 OK**

```json
{
  "id": "8b1c9d3e-7f2a-4d6b-9e5c-1a2b3c4d5e6f",
  "title": "Review case file CR-2026-0142",
  "description": "Initial triage and assign to clerk.",
  "status": "in_progress",
  "due_at": "2026-05-20T09:00:00Z",
  "created_at": "2026-05-12T14:30:00Z",
  "updated_at": "2026-05-12T15:05:11Z"
}
```

**Response — 400 Bad Request**

Returned when `id` is not a valid UUID.

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "Path parameter 'id' is not a valid UUID"
}
```

**Response — 404 Not Found**

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "Task 8b1c9d3e-7f2a-4d6b-9e5c-1a2b3c4d5e6f not found"
}
```

### PATCH /tasks/{id}/status

Update the status of a task. This is the only field that can be updated, per the brief.

**Path parameters**

- `id` — UUID v4.

**Request**

```json
{ "status": "in_progress" }
```

**Response — 200 OK**

Returns the full updated task.

```json
{
  "id": "8b1c9d3e-7f2a-4d6b-9e5c-1a2b3c4d5e6f",
  "title": "Review case file CR-2026-0142",
  "description": "Initial triage and assign to clerk.",
  "status": "in_progress",
  "due_at": "2026-05-20T09:00:00Z",
  "created_at": "2026-05-12T14:30:00Z",
  "updated_at": "2026-05-12T15:05:11Z"
}
```

**Response — 400 Bad Request**

Returned for a malformed `id` path parameter.

**Response — 404 Not Found**

Returned when no task has the given `id`.

**Response — 422 Unprocessable Entity**

Returned for an unknown `status` value or a missing `status` field.

```json
{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Request body failed validation",
  "errors": [
    { "field": "status", "message": "value is not a valid enumeration member; permitted: 'todo', 'in_progress', 'done'" }
  ]
}
```

---

### DELETE /tasks/{id}

Delete a task by ID.

**Path parameters**

- `id` — UUID v4.

**Response — 204 No Content**

Empty body.

**Response — 400 Bad Request**

Malformed UUID. Same shape as the `GET /tasks/{id}` 400.

**Response — 404 Not Found**

Same shape as the `GET /tasks/{id}` 404.

## Error shape

All error responses share the same Problem-Details-style body:

```json
{
  "type": "about:blank",
  "title": "<short reason phrase>",
  "status": <HTTP status code>,
  "detail": "<human-readable explanation>",
  "errors": [ ... ]
}
```

- `type` — URI identifying the problem type. `about:blank` until we have a typed error vocabulary.
- `title` — short, reusable label (matches the HTTP reason phrase).
- `status` — duplicates the HTTP status for convenience.
- `detail` — human-readable explanation specific to this occurrence.
- `errors` — optional array of field-level errors, present for `422` responses.
