## Scope

Exactly the checklist in `plans/backend.md` under `backend-2`:

- `Task` SQLAlchemy model. Fields: `id` (uuid, PK), `title` (str, 255, not null), `description` (text, nullable), `status` (enum `todo`/`in_progress`/`done`, default `todo`), `due_at` (timezone-aware UTC, nullable or not — match the brief), `created_at` and `updated_at` (timezone-aware UTC, server defaults).
- Alembic autogenerated migration. Inspect the SQL: enum type created, indexes sensible, defaults correct.
- Pydantic v2 schemas: `TaskCreate`, `TaskUpdateStatus`, `TaskRead`.
- Shared `TaskStatus` enum used by both model and schema.

## TDD discipline

Write the failing test first, one behaviour at a time.

1. `tests/test_task_model.py`: a test that round-trips a Task through the DB — create a row with title, status, due date; read it back; assert fields match. Use a pytest fixture that gives you a session against a clean ephemeral schema (or a transactional rollback fixture). Run pytest, watch it fail because the model doesn't exist.
2. Add the model. Watch it go green.
3. Next test: a Pydantic `TaskCreate` rejects an empty title, accepts a 255-char title, rejects a 256-char one.
4. Next test: `TaskCreate` rejects an unknown status string.
5. Next test: `TaskCreate` rejects a naive (timezone-less) `due_at`.

Commit at green for each cycle. The migration is generated and verified by running `alembic upgrade head` against the compose Postgres.
